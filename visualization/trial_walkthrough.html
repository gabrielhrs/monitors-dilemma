One HSVI trial, worked end to end

Trial 5 (0-indexed iteration 4) from the actual solver run on the 3-action game, root partition 2, prior belief P(Schemer)=0.25.

This is one real trial pulled out of the interactive convergence tree and laid out as a straight line, because it's a clean illustration of the two things that make this whole approach work: a persistent belief that accumulates evidence across all 8 rounds, and a monitoring policy that gets to choose, round by round, how hard to look. It's also a clean illustration of the division of labor between the two checks: Audit is what actually resolves belief here, not Cheap.

Round 1 opens with an Audit -- expensive, but it always tells the truth. This time it comes back finding a real attack, and belief snaps straight from the 0.25 prior to 1.000.

Round 2 audits again (budget allows one more) and confirms it: ATTACK again. From here on nothing can move belief off certainty. Budget is now spent, so Round 3's Cheap check on fibonacci comes back "clear" and Round 4's Pass reports nothing -- both are real observations, but neither can undo what two Audits already established.

Notice what's missing from this trial: a Cheap check ever coming back FLAG. That's typical, not a coincidence of this one run -- Cheap's catch odds are k probes divided by how much of the problem's input space the bug is actually reachable from, and for most of these eight problems that's small: fibonacci 16.7%, is_prime 10.9%, sum_of_digits 0.025% (its domain is 20,000 possible inputs), and effectively 0% for the rest, whose bugs aren't confined to any small, checkable range at all. A signal that weak rarely produces a dramatic "gotcha" -- Audit, which always tells the truth, is what actually does the detection work in this game. Cheap is better understood as a small, mostly-uninformative nudge that's cheap enough to be worth running anyway.

That's still the point of carrying belief as a persistent, single running number across the whole session instead of resetting it each round -- Audit, not a lucky Cheap flag, is what actually supplies hard evidence in this game. Once two independent Audits agree, the belief stays pinned at 1.000 for every remaining round in the trial, because the game is still using everything it's seen from round 1 onward.

What this trial's backup did to the root's own bounds

Before this trial, the value function's estimate of the whole 8-round game (at the root's belief 0.25) sat in [-59.810, -58.325] -- a width of 1.485, still fairly uncertain. This trial's forward walk (the peek phase, above) picked a path that runs straight into a double-Audit-confirmed attack; its backward pass then propagated that new information about the path's worst case all the way back up to the root, narrowing the estimate to [-59.279, -58.325] -- a width of 0.954. One trial cut the remaining uncertainty at the root by 36% -- entirely by tightening the lower bound; the upper bound didn't move this time.

That's HSVI's whole strategy in miniature: don't try to evaluate every belief point to full precision. Pick one promising trajectory, walk it forward, then let a single backward pass tighten the bounds everywhere along that path -- including, most importantly, back at the root, which is the only number that actually decides how the game is being played right now. Repeat a few dozen times (31, for this game) and the root's own gap between lower and upper bound shrinks from 8.27 down to 0.041 -- see the full convergence tree for the entire run.
