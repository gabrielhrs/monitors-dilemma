Reconstructed belief-to-action policy

Every trial we've shown so far played out one belief path at a time. This page asks a different question: at any belief P(Schemer), which action does the solved game actually recommend? For each partition (a round x audit-budget pair), the solver keeps a set of lower-bound alpha-vectors, each carrying a mixed action attached to it. Evaluating the value function at a belief already computes max_j alpha_j · belief to pick the best vector -- the only change needed was a small addition to the solver's value-function code to expose which vector j won, so we can read off its attached strategy. That's the same move as the alpha-vector-to-policy reconstruction from the L4DC paper, applied here to sweep belief from 0 to 1 and see where the recommended action actually changes -- no LP solving involved, just evaluating the alpha-vectors already sitting in memory once the solve finishes.
Pass Cheap Audit never backed up (still the arbitrary uniform default)
Two hatched cells, explained: partitions at round 1 / budget 0 and round 2 / budget 0 (below) are structurally unreachable from the actual starting budget of 2 -- reaching budget 0 that early would mean spending both audits before round 1 even starts, which the game's rules don't allow. HSVI is a targeted search, not exhaustive dynamic programming, so it correctly never visits belief points that can't occur, and those two partitions show up hatched below rather than as a real (if untrained) policy.

Round x audit-budget grid

An emergent threshold, not a designed one: partition 2, round 1 at full budget, is the root of the whole game. Its policy is a mostly-Audit mix for belief up to about 0.89, then flips to deterministic Audit above that. Partition 4 (round 2, budget 1) shows the same shape with its own threshold at 0.30; partition 10 (round 4, budget 1) flips at 0.38. The budget-0 partitions don't all move together: fibonacci (partition 6, catch odds 16.7%) flips Pass→Cheap early, at belief 0.04; is_prime (partition 15, catch odds 10.9%) flips a little later, at 0.06; but sum_of_digits (partition 18, catch odds 0.025%) never flips at all -- Pass wins at every belief from 0 to 1. Spending -0.2 for a real-world catch chance under 0.03% simply never pays for itself, no matter how certain the Monitor is that it's facing a Schemer. None of these thresholds were designed in -- they fell out of solving the game.
Where the scarce audit actually goes: partition 16 (round 6 = is_prime, budget 1) settles on Pass for belief up to 0.04, then deterministic Cheap from 0.05 up to 1.0 -- Audit doesn't appear in this partition's policy at all. That's because is_prime's real catch odds (10.9%, since only primes under 200 actually reach the modified branch) make Cheap alone good enough here, freeing up the single remaining audit for a round where Cheap does nothing at all. That's exactly what happens two rounds later: partition 19 (round 7 = sum_of_digits, budget 1) flips straight from Pass to deterministic Audit at belief 0.06, with no Cheap segment in its policy whatsoever -- consistent with sum_of_digits' 0.025% Cheap catch odds being useless regardless of belief. is_prime's real domain (46 reachable primes) makes it only modestly better than Cheap-blind problems, so the policy reallocates its scarce audit toward the round where Cheap truly can't help at all.
