HSVI Convergence Tree -- the real trial-by-trial trace of the actual solver converging on the toy control game (games/hsvi_trace.jsonl -> games/convergence_tree.json). Each node is a distinct (round, budget, belief) point the solver actually queried; drag the slider to replay the 29 trials it ran before width < eps. Nodes fade in as they're first visited; the trial running at the selected iteration is highlighted in yellow. Each node shows its lower/upper bound as of that iteration -- watch the gap between them shrink over trials, and watch the same (partition, belief) point get revisited and tightened across iterations. The tree is wide (85 nodes) -- nodes use short codes for the coding problems and compact labels for budget/belief/bounds (see "What the labels mean" below), and the pan slider or the panel's own scrollbar move the view horizontally. The "Trial spotlight" panel below the chart shows, for whichever iteration is selected, the one trial's actual belief trajectory (root to frontier) and exactly what that trial's backup did to the root's own LB/UB -- this is the rationale for the whole method: each trial picks a promising path, walks it forward, then narrows the bounds on the way back up.
What the labels mean

Monitor actions (edge labels, before the "/")

Pass
No check at all. Free (cost 0), but gives zero information -- belief never changes after a Pass, regardless of what it was before.
Cheap
k=5 random black-box probes against a reference implementation. Costs -0.2. Only has real power on "bounded" domains (18% chance of catching a live attack); on "unbounded" domains it's blind (0% catch), per the actual measured elicitation data.
Audit
Full reference check. Costs -1 and draws down the audit budget (starts at 2), but always reveals the truth for that round (100% catch rate).

Observations (edge labels, after the "/")

none
The non-observation from a Pass.
clear
A Cheap-check ran and found nothing. Real (if weak) evidence of innocence on bounded domains; uninformative on unbounded ones.
flag / FLAG
A Cheap-check ran and caught something. The measured false-positive rate is exactly 0.000, so this is treated as fully diagnostic -- belief jumps straight to P(Schemer)=1, overriding any accumulated "clear" evidence.
revealed_honest / honest
An Audit ran and found nothing -- but not necessarily proof of innocence: the solver's worst-case adversary strategy can have a Schemer sometimes play Honest too, so this can leave belief at a small nonzero value rather than exactly 0.
revealed_attack / ATTACK
An Audit ran and found a real attack. Always fully diagnostic -- belief jumps to exactly 1.

Node contents

domain strip (orange = unbounded)
The coding problem's domain type for that round -- public information, fixed per round, not something the Monitor infers.
domain strip (green = bounded)
Same as above; bounded domains are the ones where Cheap-checks actually help.
P(Schemer)
The Monitor's current belief that the hidden, persistent type chosen once at the start of the whole 8-round session is "Schemer" (adversarial) rather than "Benign." Persistent means one flag or reveal updates the risk assessment for every remaining round too, not just this one.
LB / UB
The solver's lower and upper bound on the game's value at this exact belief point, as of the selected iteration, shown compactly as "lb / ub". The gap between them is the remaining uncertainty; watch the small yellow bar under the numbers shrink as trials tighten it.
b= / P(S)=
Short for "budget=" and "P(Schemer)=" -- shrunk to fit the smaller node.
Problem codes
FMAX=find_maximum, PAL=is_palindrome, FIB=fibonacci, REV=reverse_string, VOW=count_vowels, PRM=is_prime, SUM=sum_of_digits, DUP=remove_duplicates.

Highlighting

yellow border
This node was visited (peeked or backed up) during the specific trial running at the currently selected iteration.
bold yellow edge
This edge's child node was discovered for the very first time at this iteration -- the trial extended the search past the previously-known frontier here.
thin yellow edge
Both ends of this edge were touched by the current trial this iteration, but the child was already known from an earlier iteration -- the trial is re-descending already-explored ground on its way to the frontier (HSVI's "peek" step) rather than discovering anything new. Without this, a trial's walk can show yellow-bordered nodes with no visible yellow trail connecting them back to the root.
faded / dim nodes
Not yet visited by any trial up to the selected iteration -- move the slider forward to reveal them.
